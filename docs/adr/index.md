# Architecture Decision Records

This directory contains the Architecture Decision Records (ADRs) for the Patorbit Knowledge System.

ADRs are short, written documents that describe a significant architectural choice made by the team. Each ADR includes the context of the decision, the decision itself, and the consequences of that decision.

## Process

1.  **Propose**: When a significant architectural decision is needed, create a new ADR using the template. The initial status is `proposed`.
2.  **Discuss**: The ADR is discussed with the team via a pull request.
3.  **Decide**: Once consensus is reached, the ADR is updated with the decision and its status is changed to `accepted`. If the proposal is rejected, its status becomes `rejected`.
4.  **Implement**: The architectural decision is implemented.

Once an ADR is `accepted`, it is immutable. If a decision needs to be changed, a new ADR is created to supersede the old one.
