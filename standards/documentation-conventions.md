# Documentation Conventions

## Language & Tone

- Use **American English** spelling.
- Use **clear, concise language** — avoid passive voice where possible.
- Address the reader directly ("you") where appropriate.
- Keep paragraphs short (3-5 sentences max).

## File Structure

- One concept per file.
- Use `README.md` for directory index pages.
- Document WHY not just WHAT — explain rationale.

## Linking

- Use relative links between internal docs (`[text](../path/to/file.md)`).
- Use absolute URLs only for external references.
- Link to the standards directory for recurring conventions.

## Code Blocks

- Always specify the language (` ```typescript ` not ` ``` `).
- Use `bash` for shell commands, `typescript` for TS code, `json` for JSON.
- Keep line length under 100 chars in code blocks.

## Headers

- Use `#` for title (one per file).
- Use `##` for major sections.
- Use `###` for subsections — avoid `####`+ unless essential.
- Headers use sentence case ("Documentation conventions" not "Documentation Conventions").
